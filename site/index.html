ante

A small, mandatory proof-of-work commitment for Freenet identities — the step between no effort at all to sybil and a ghost key.

A guestbook or a comment box on a decentralised network has no server to rate-limit at, no account to suspend, no IP worth blocking. Ghost keys solve identity properly, but they cost real money and involve a third party — absurd friction for signing a guestbook.

ante fills that gap. An app asks your ante key for a signed proof that it burned a measurable slice of CPU for this specific action. Checking one is a single hash and a single signature check, by anyone, with no network access and nothing to trust.

What a proof means

It proves the key cost something for this exact purpose. That is the whole claim.

It does not prove the key is unique, human-held, or not one of thousands an attacker made — each costs the same. It is not proof of personhood, and it does not resist anyone with real hardware. It is a floor, not a ceiling; ghost keys and reputation sit above it.

Your key

One Ed25519 key, held by your own Freenet node and shared across every app that uses ante — so work you commit in one place counts everywhere. The private half never leaves your node: apps see the public key and finished proofs, and using it raises a consent prompt your node draws, not the app. You can tell an app you trust to stop asking — the vault lists every app you have done that for, and revokes any of them.

Because it is yours, it is yours to lose. Save its recovery code.

Apps

  • ante vault Create your key, raise its level, manage which apps may use it, and save its recovery code.
  • ante guestbook A working example: every post carries proof of work, and entries are ranked by how much their author spent.

Those addresses are the apps. Nothing here reads an address from the URL — a link that could repoint one would let anyone show you their data under a genuine address. Check what you open against this list.

How it works

You grind a nonce until blake3(challenge ‖ nonce) starts with enough zero bits, where the challenge binds a purpose string and your key. Your node signs the result. Anyone can recompute the bit count from the nonce — it is never stored, so it can never be overstated.

Each extra bit is twice the work. In a browser that means roughly a second for 18 bits, ten for 20, a minute for 24.

Using it in your app

Four calls. The delegate ships inside the client — nothing to deploy.

const ante = await AnteClient.attach(fn);

const outcome = await ante.commit("myapp:post:v1", { minBits: 18 });
// attach outcome.proof to your contract write

verifyAnteProof(entry.proof, 18);   // in the browser
proof.verify(18)?                   // in your contract, via ante-core

Bind the proof to what it pays for — put the message digest in the purpose string, or one grind buys unlimited actions. And note a proof is not a token: it never expires and nothing marks it spent, so if repeating an action means something in your app, dedupe it yourself. The guestbook example shows the whole integration, and the whitepaper explains why both rules exist.
